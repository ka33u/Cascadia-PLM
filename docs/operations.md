# 数据迁移与运维

## 新建环境

先创建 PostgreSQL 空库并配置 `.env`，执行 `npm run setup`。容器入口会运行迁移和首次初始化；已存在账号时不会重置密码。初始化完成后可从本机环境中移除 `ADMIN_PASSWORD`。系统不会将密码写入日志或 Git。

附件目录由 `ATTACHMENT_ROOT` 指定，默认 `runtime/attachments`。目录应由服务账号独占写入，不要将其作为静态网站目录暴露。所有下载经接口校验当前归属与文件 SHA-256。

## 从旧版迁移

1. 保留旧源码和数据库备份，停止旧应用写入。
2. 建立新的空数据库；将 `.env` 的 `DATABASE_URL` 指向新库，执行 `npm run db:migrate`。**此时不要执行 setup**，迁移器要求目标没有用户、项目、模板或附件。
3. 在本机环境配置 `LEGACY_DATABASE_URL` 为旧库地址；如果存在附件，配置 `LEGACY_ATTACHMENT_ROOT` 为旧文件库绝对路径，`ATTACHMENT_ROOT` 为新的附件目录。
4. 执行 `npm run migrate:legacy`。输出逐表计数，不输出密码。核对迁移报告；任何关联错误、损坏附件、重复身份或目标已有数据都会使迁移停止。
5. 执行 `npm run setup` 补齐默认导入模板，然后 `npm run build`、`npm start`。用原邮箱和密码登录，并按提示修改密码。
6. 核对账号、项目、BOM 版本及原始文件、承诺历史、问题状态和附件后，切换入口地址。

迁移保留原 UUID、密码摘要和业务日期；旧会话不复制。旧库只读、不清空。数据库写入整体提交；迁移中断可能在新附件目录留下已校验的孤立文件，重试会核对相同内容，不覆盖冲突文件。

测试迁移 `npm run test:migration` 会创建两个以 `_test` 结尾的临时数据库，需测试账号有建库权限。测试库保留，便于检查回滚和完整性。

## 备份与恢复

使用 PostgreSQL 标准 `pg_dump --format=custom` 备份独立数据库，同时备份整个 `ATTACHMENT_ROOT`。密码通过本机 PostgreSQL 环境变量或密码文件传递，避免写入命令历史。

附件上传后内容不可变，归档保留原文件。应先完成数据库快照，再复制附件；备份期间不要直接修改文件目录。恢复时用 `pg_restore --single-transaction --no-owner --no-privileges` 导入另一个空库，恢复配套附件目录并运行登录、原始 BOM 下载、附件下载和齐套核对后再切换入口。不要对正式库执行 drop、reset 或回归测试。

## 运行与升级

`npm run dev` 的页面端口默认 3410、接口端口 3411；`npm start` 单端口 3410 同时提供构建后的页面和接口。健康检查为 `/api/health`，会实际检查数据库连接。

上线使用 HTTPS，`BASE_URL` 与浏览器访问地址保持一致。反向代理只需转发至应用端口；所有写接口要求同源请求。应用不信任任意传入的 `X-Forwarded-For`，代理后登录频率限制会以代理连接来源计数；大规模部署可在受信任代理层进一步配置来源限流。

升级先备份，再安装锁定依赖、运行数据库迁移、类型检查与构建，最后重启服务。迁移脚本随 Git 版本管理；回归必须配置独立的 `_test` 数据库。
