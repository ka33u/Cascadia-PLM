# 项目历史完整浏览

依据规格书BR-05、19.2、20、UI-09及28.2，要求、承诺、实际完成及相关变更应可追溯。

此前项目详情只携带最新100条动态，“承诺与动态”页直接显示这批记录，无法继续查看数据库中更早的完成、更正、BOM及项目操作。本轮新增独立的项目动态分页接口，历史页面可以翻到更早记录；概览仍使用详情中的少量最近动态。

## 页面行为

- 承诺历史每页25条，可按物料、编码、回复人、承诺日期或原因搜索，区分首次回复和日期改期，选择最新或最早在前。搜索覆盖该项目全部承诺历史，保留已停止跟踪物料的查看入口。
- 项目动态每页25条，提供最新记录、上一页、更早记录；可按关键词、承诺回复、完成与更正、BOM与跟踪、项目阶段、问题、资料和其他记录筛选，日期按北京时间的自然日范围查询。
- 动态显示事项、操作人和发生时间；完成记录显示实际日期，更正显示前后日期，原有项目调整、继承、母件确认等说明保留。概览与历史页共用动作名称。
- 承诺与动态分别筛选、翻页，顶部提供两个区域的直达按钮。手机把日期成对排列，长原因与备注自动换行。
- 读取失败可以重试；新筛选读取期间隐藏旧条件结果，迟到响应不能覆盖新查询或其他项目。刷新“最新记录”可以看到翻页期间新增加的动态。

动态接口从数据库分页，承诺历史目前仍随项目详情完整读取、在前端分页。操作人名称来自当前用户信息，部分原始变更详情另保留操作时姓名；用户编号和原始事件详情不被此次界面改写。

## 接口

`GET /api/v1/npi/projects/:id/events`

| 参数 | 约束 |
|---|---|
| `limit` | 默认25，整数1～100 |
| `before` | 上页返回的 `nextCursor`，为同一项目中一条动态的UUID；首请求省略 |
| `category` | `all`、`promises`、`completion`、`bom`、`project`、`issues`、`files`、`other` |
| `q` | 最长200字，字面查找事项当前名称、操作人及原始记录内容，`%`和`_`不作为通配符 |
| `from` / `to` | 可选 `YYYY-MM-DD`，北京时间起止自然日均包含；开始不得晚于结束 |

返回 `{ projectId, items, nextCursor, limit }`，每项包含事件原字段及 `actorName`、`objectName`。没有更早匹配项时 `nextCursor` 为null，不伪造全量总页数。翻页以数据库的 `(created_at,id)` 为边界，保留微秒精度；不使用会随新增记录偏移的行号。承诺列表沿用详情接口给出的数据库顺序，避免浏览器把同毫秒内记录按编号重新排乱。

每次读取重新验证项目权限；技术／制造仅查看本人负责项目，主管／管理员可查看授权范围，采购和仅被分配单个物料的人员不能由此读取整个项目历史。异项目或不存在的游标会被拒绝。本轮复用现有表，无数据库迁移。

## 验证范围

接口专项遍历140条记录，覆盖同一毫秒内137条动态、翻页期间新增记录、北京时间边界、字面搜索、类型筛选、查询校验、角色隔离与负责人变更后的权限回收。自建数据结束清理。

浏览器专项遍历133条旧动态的6页及53条承诺的3页，验证首次／改期筛选、最早与最新顺序、历史区域直达、独立翻页、完成更正详情、失败重试、迟到查询和跨项目隔离。53条承诺夹具被安排在同一毫秒内，以验证页面顺序保留。主管浏览全程无业务写请求。

使用独立无头Chrome、临时服务与显式 `_test` 数据库；未改正式业务数据。另有4项概览DOM回归、标准类型检查与构建。详见 [验证记录](project-history-verification.json)。这些专项不替代真实项目试运行、全系统并发压力或整份规格书最终验收。

从项目目录执行（须配置独立 `TEST_DATABASE_URL`；浏览器先构建）：

```sh
TSX_TSCONFIG_PATH=packages/core/tsconfig.json node --env-file=.env --import tsx scripts/npi-project-events-http.test.ts
npm run build
TSX_TSCONFIG_PATH=packages/core/tsconfig.json node --env-file=.env --import tsx scripts/npi-project-history-browser.test.ts
```

实际构建首次验证时，单次503拦截被开发模式的首次Effect重放消耗，另一读取成功，导致故障提示断言失败。诊断确认两次初始请求；测试改为在验证错误显示前持续模拟故障，随后恢复接口并显式点击重试，实际构建专项通过。此修正仅调整故障注入，没有为通过测试改变业务行为。
