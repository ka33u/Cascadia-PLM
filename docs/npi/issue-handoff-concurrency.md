# 问题交接并发校验

问题写入接口先取得项目事务锁，再重新读取问题的当前负责人、删除状态和项目归属。若旧采购负责人的请求曾等待交接事务，交接提交后会按最新归属重新校验，不能沿用等待前的权限继续写入处理记录。

这项修复适用于问题修改、补充处理记录和状态推进共用的权限检查。交接后，新负责人仍能正常记录进展；原负责人不能查看或修改该问题。

## 验证证据

新增接口回归在隔离 `_test` 数据库中执行：

1. 用事务持有项目锁并更新问题负责人，暂不提交。
2. 原负责人通过真实 HTTP 提交处理记录。
3. 查询 PostgreSQL 锁等待信息，确认该请求确实被交接事务阻塞。
4. 提交交接，检查旧请求返回 403、问题时间线未增加该记录。
5. 检查新负责人提交成功，旧负责人读取被拒绝。

同一用例在修复前返回 201，证明旧请求可以越过交接；修复后通过。完整 NPI 接口回归共 35 项通过。

测试使用合成项目和账号，不写正式业务数据库。该修复不改变已确认的负责人选择规则，处理记录的重复请求规则见 [处理记录重试](issue-note-retry.md)。
