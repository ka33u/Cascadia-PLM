# 制造回复保存恢复与计划核对

对应规格书19.6、20、22和28.4：制造一次回复四节点，改期原因和首次承诺留存，手机回复简短，齐套页面保留集中回复区。

## 交互变化

集中回复弹窗与齐套页底部表单继续共用组件。已确认保存、随后项目或任务列表读取失败时，保留“已保存”提示并锁定日期，提供“重试刷新列表”。重试只读取，不再次提交制造承诺。所有读取成功后，弹窗关闭；内嵌表单恢复可编辑。下方当前承诺在等待刷新期间显示刚确认写入的日期，避免显示为旧的待回复状态。

提交失败或响应不明确时，保留日期和原因，暂停再次保存；先点击“刷新最新计划”，再显式“载入最新计划”。已编辑且仍未完成的节点保留草稿，未编辑节点采用最新承诺；已完成节点采用最新记录并保持锁定。表单下方同时显示要求、当前承诺和实际完成日期，方便比较。载入时若某个草稿已成为服务器当前承诺，再次点击保存不会重复写入。

同步操作标记阻止同一窗口连续提交。保存、读取和刷新期间不能关闭弹窗，也不能打开异常件表单。读取失败保持写入锁定，重新读取时核对账号、项目和当前制造负责人；切换项目后旧读取不覆盖新项目。

## 验证范围

- 已在修改前的组件复现保存失败恢复缺项：已写入但刷新失败后，没有只读重试入口。该断言在候选版通过。
- 新增6项组件检查，另回归5项资料窗口检查，共11项通过。包括连续刷新失败、同步重复提交、响应丢失、冲突草稿和原因保留、已完成节点锁定、读取失败、负责人变化以及内嵌表单恢复。
- 浏览器专项使用两个自建测试项目：A保存后连续两次汇总读取失败，承诺只写入一次；后续模拟另一会话更新工装，工艺草稿和原因在核对后保留。B从内嵌表单提交后丢失响应，重新读取不产生重复记录；第二次提交后的账号不一致阻止刷新，随后仅重试读取。
- A共3次PUT（含1次409冲突）、3条承诺历史（含另一个会话的工装回复）；B共2次PUT、2条历史。首次工艺承诺、改期原因、节点和项目归属保持正确。
- 候选、实际构建与原制造快捷回复专项回归，以及390×844手机和1440×1000桌面检查；详细结果见[验证记录](manufacturing-recovery-verification.json)。
