# 制造任务直接确认完成

依据规格书19.6、22与28.2：制造负责人集中处理四节点，手机日期回复与确认完成控制在三步以内。

“制造准备”的未完成任务增加“确认完成”，点击后直接打开四节点表单：选择任务、填写实际日期、保存。项目内“集中确认完成”使用同一表单。页面说明同步改为直接回复和确认完成，完整历史仍可进入项目查看。

只填写本次完成的节点，其余留空；至少填写一项，实际日期不得晚于今天。已有实际日期展示但锁定。保存复用既有制造完成接口，保留完成审计和首次／当前承诺历史，更新任务计数与齐套状态；不是推进项目阶段或改写已有完成日期。

遇到并发冲突或提交结果不确定，表单保留输入并暂停提交。读取最新记录后，已完成节点显示最新实际日期并锁定；选择“按最新记录继续”保留其余未完成节点的输入。负责人变更、项目结项或无法核对权限时停止编辑。更正既有实际日期仍走原受控更正入口。

保存、读取及刷新期间不能通过取消、关闭按钮或Escape关闭表单。完成已保存但列表刷新失败时，显示“重试刷新”，只重新读取详情与列表，不再次提交完成。切换模块后到达的旧项目读取不会打开过时表单；不同项目的输入不共用。

桌面两列、手机单列显示四节点，压缩表单间距，保留项目标识、要求日期和承诺日期。主管与技术人员通过项目详情查看，制造负责人及管理员可确认完成；后端权限规则沿用原实现。

## 验证

专项使用独立无头Chrome、临时应用服务与显式隔离 `_test` 数据库，自建项目、账号和会话结束清理，不修改正式业务库。覆盖：

- 手机从任务直接打开表单，空日期和未来日期不提交，部分完成后计数刷新。
- 并发完成冲突，最新实际日期锁定，未完成节点输入保留，显式核对后再保存。
- 成功写入后模拟列表503；重试仅发读取请求，完成事件不重复。
- 读取失败恢复、负责人变更后的锁定、跨项目输入隔离及迟到导航读取。
- 管理员一次完成四节点；主管和技术页面无完成写入入口；原承诺历史不变。
- 桌面1440×1000、手机390×844，标题和保存按钮在可视区域内。

同时回归既有制造快捷回复，确保日期改期、历史、冲突恢复和保存期间保护不受影响。旧完整BOM浏览器脚本仅更新受新表单影响的选择器与已完成字段断言，本轮未运行其全部流程。最终交付证据见 [验证记录](manufacturing-completion-verification.json)。

运行专项（从应用目录，必须配置 `TEST_DATABASE_URL`）：

```sh
TSX_TSCONFIG_PATH=packages/core/tsconfig.json node --env-file=.env --import tsx scripts/npi-manufacturing-completion-browser.test.ts
```
