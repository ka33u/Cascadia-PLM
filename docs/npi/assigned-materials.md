# 技术与制造人员的协作物料待办

问题：原表单允许把临时样机件或BOM跟踪物料分给本项目负责人之外的技术/制造人员，保存与回复接口认可该责任人，但其项目首页和承诺历史不可见。隔离复现中“分配成功、项目列表0项、项目与历史403、直接回复成功”。

本次增加本人工作台接口`GET /api/v1/npi/workbench/materials`，仅技术/制造岗位可调用，按当前用户ID和物料跟踪类型筛选；不返回他人任务。承诺历史同样允许当前物料责任人读取自己的材料记录。项目、BOM全树等读取权限保持项目范围，不因单项分配而开放整个项目。

技术/制造首页新增“我的协作物料”，放在项目指标前。仅在存在其他项目分来的物料时显示；本人负责项目的物料仍从原项目入口处理，以免重复列表。支持项目/编码/物料搜索、状态筛选、20项分页、首次回复、填写原因改期、实际完成和历史。已完成记录可通过筛选查看，关闭项目不提供修改按钮。

回复使用现有版本校验、首次承诺、原因和完成幂等规则。保存成功先退出编辑；若后续列表刷新失败，保留成功提示和旧列表，禁用操作并允许重新读取，不重发保存请求。登录账号写入上下文仍由服务器核对。

交接后原接收人从个人列表消失，且无项目权限时不能再读取该项历史；接任人能看到保留的首次承诺和完整历史。原项目负责人仍按项目权限查看记录。

此入口聚焦日期回复与完成。本轮未增加其他类别的物料类型，也未放宽项目资料、文件或问题权限；“其他物料”类型及协作人员的文件需求仍应单独完善。

验证：HTTP回归新增本人范围、整项目/BOM拒绝、历史、回复、交接撤权；浏览器脚本`scripts/npi-assignment-browser.test.ts`验证390px手机与桌面、保存成功后读取失败、无重复保存、改期历史和完成。业务写入只在隔离测试库。

运行浏览器验证前先在候选/本地构建应用，再执行：

```sh
TSX_TSCONFIG_PATH=packages/core/tsconfig.json node --env-file=.env --import tsx scripts/npi-assignment-browser.test.ts
```

脚本使用`TEST_DATABASE_URL`，独立临时端口及独立无头浏览器，不操作用户已打开的窗口。运行库和待同步配置页文件不受此次修改影响。
