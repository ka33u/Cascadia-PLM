# 资料上传与归档期间的操作保护

对应规格书19.7、22和28.2：物料到货资料、手机问题照片、项目附件及历史追溯。本轮补齐这些资料操作的窗口保护。

## 当前行为

物料附件、个人协作物料附件和项目问题详情，在资料上传／归档及其后续刷新完成前保持打开。关闭按钮、Esc和点击遮罩都不能关闭正在保存的窗口；完成或请求失败后恢复关闭。窗口显示正在进行的操作，归档期间同时锁定原因和取消按钮。

组件在提交时同步记录操作编号，阻止同一窗口连续触发重复写入；旧窗口的迟到回调不能解除新窗口的保护。上传成功但资料列表刷新失败时，保留成功提示，用户可单独刷新列表，无需重新上传。上传失败则保留所选文件，继续沿用原有当前表单重试编号。

问题详情内，资料保存期间暂停记录进展、修改状态和刷新问题。反过来，问题记录正在保存时，附件表单暂时不可操作，已选择的文件仍保留。现有资料访问权限、Document/Vault存储和归档记录沿用原服务。

## 验证

- 13项组件检查通过，其中新增5项，另含个人协作附件和问题刷新恢复的8项回归。覆盖连续提交、失败恢复、关闭保护、旧窗口回调隔离和问题／资料操作协调。
- 候选与同步后的实际构建均通过独立浏览器专项。物料上传、归档和问题照片上传各只有一次POST；窗口对Esc、关闭按钮和遮罩点击保持打开，写入完成后可正常关闭。
- 归档原因被保留，归档事件只有一条，归档文件可下载且字节与原文件一致。问题附件关联正确，资料上传期间没有额外的问题进展写入。
- 手机390×844与桌面1440×1000验证通过，手机页面没有横向溢出；采购到货后补资料专项在实际构建上回归通过。标准类型检查、脚本类型检查、ESLint、格式检查和构建通过。

## 测试与边界

浏览器使用独立无头Chrome、显式 `_test` 数据库和临时Vault，清理本次自建项目、账号、会话、原生资料及文件，保留共享测试库已有数据。调试中曾因测试脚本错误地要求上传返回200而中断；接口实际返回201。该次遗留的两个测试项目、四个测试用户和临时文件已经按记录清理，脚本已改为在主流程检查响应，确保异常进入清理分支，并增加夹具清单及未清理时停止运行的保护。修复后的候选与实际两轮均正常退出并完成清理。

本轮保护范围是上述资料弹窗以及问题弹窗。不拦截关闭整个浏览器、整页刷新或项目内联资料页的标签切换；不改变后端权限、日期或归档规则。专项通过不代表全部规格书签收或真实业务试运行完成。
