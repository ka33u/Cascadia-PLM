# BOM外物料新增恢复与技术资料

依据规格书8、19.8和22：技术或制造新增BOM外物料，指定回复人后进入待办，并可补充技术PDF或图片。

## 使用流程

填写物料信息后可选择“保存”或“保存并补充资料”。后一入口在新增和清单刷新成功后打开刚创建物料的附件，资料按该物料编号关联。采购件进入采购责任人的待回复清单，临时样机件和其他物料进入指定技术／制造人员的协作清单；影响齐套的物料参与预测。

如果已新增但清单读取失败，表单显示已保存，锁定内容，提供“重试刷新列表”，不再发起新增。选择补资料的意图在刷新重试期间保留。新增后核对返回的项目、账号和物料编号，其他物料不能接收本次资料。

如果网络丢失提交响应，表单保留并锁定本次内容，可“重试本次保存”。这会发送相同请求编号和内容，服务器返回已创建记录，不重复新增。明确的400／422校验拒绝允许修改内容后重新提交。保存、重试和刷新期间阻止重复操作和误关窗口；出现错误时自动滚回提示位置，手机上可直接看到重试入口。

## 接口与数据约束

`POST /api/v1/npi/projects/:id/external-items`新增可选UUID字段`requestId`。未传该字段的既有调用保持原行为。传入后以项目、当前账号和请求编号识别本次提交；同一编号的不同内容返回409，同一内容重复调用仍返回201及同一个物料ID。

项目行锁串行保护“查找已提交记录→新增”整个事务，创建事件与物料写入一起提交。事件保存请求编号和字段摘要，无需增加数据表或执行迁移。重试返回当前物料状态，不覆盖其后续承诺、供应商或完成历史；原责任人停用也不会促使重复创建。每次调用仍先校验当前账号、项目权限和项目未完成状态，交接后的原项目负责人不能借请求编号获取结果。

主动再次新增、不同账号或不同项目使用独立提交范围，允许合法同名物料存在。不通过物料名称或数量相似度去重。数量以十进制文本校验和保存，没有浮点转换。

请求编号仅保留在当前新增表单中。关闭表单或刷新整个页面后，应先核对项目清单，再决定是否新建；本轮未增加跨浏览器持久草稿。

## 验证

- 修改前已复现五次相同请求产生五条物料。候选接口专项中五个并发请求只创建一条物料和一条新增事件。
- 接口专项覆盖不同内容拒绝、请求编号大小写、精确数量`999999999999.123456`、首次与当前承诺保留、停用原采购人后的重试、不同账号／项目范围、无请求编号兼容、无效输入无写入、交接权限和完成项目只读。
- 7项组件检查通过：5项新增恢复检查及原三类BOM外物料的2项回归；已有36项NPI接口回归通过。
- 浏览器在两个自建项目中验证：A新增后丢失响应，重试仍仅一条物料，随后直接上传技术PDF；B校验失败后修正，再经历两次清单读取失败，仍仅一条物料。采购和制造待办各只有对应的一项。
- 技术PDF关联正确，采购责任人可下载原字节，其他采购账号被拒绝，另一个项目没有该资料。桌面与手机页面无横向溢出，手机错误提示在可见区域。
