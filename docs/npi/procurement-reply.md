# 采购日期回复与冲突恢复

依据规格书19.7、20、22及28.5，采购账号从“采购管理”的本人清单点击“回复”或“改期”，直接填写预计到货日期。首次回复只要求日期；供应商和备注放在可展开的选填区域。只有改变已有承诺日期时才要求变更原因，单独补充供应商或备注不会增加改期次数。

弹窗同时显示要求到货、首次承诺和当前承诺。保存使用打开时的记录版本，后台仍校验责任人、岗位、项目状态和版本。冲突或请求失败保留填写内容，并提供“读取最新记录”：

- 读取操作不会直接覆盖表单。
- 记录变化时显示要求、承诺、供应商和备注的前后值，暂停保存，待点击“以最新记录继续编辑”。
- 确认后保留本次手动改过的字段；没有动过的字段更新为服务端最新值，避免带回过期供应商或备注。
- 读取失败时保留表单并暂停保存，可在原弹窗重试读取。
- 物料已转交、不再跟踪、项目已完成或已经到货时停止保存，避免继续修改旧记录。

“到货”弹窗填写实际到货日期及选填说明，前端限制日期不晚于北京时间今天，后台继续执行同一校验。到货后可从清单的“附件”补充照片和到货资料，也可查看完整承诺历史。已有完成日期不通过此弹窗更正。

读取和保存期间禁用表单与取消，阻止Escape或关闭按钮误关闭；点击遮罩不会丢弃输入。手机弹窗压缩间距，保存操作随弹窗滚动保持可见。保留原管理岗位的物料操作入口，不新增API、权限或数据库迁移。

## 本次验证

独立浏览器使用显式隔离的 `_test` 数据库、两个临时项目、三个采购物料和四个临时账号，验证首次日期回复、改期原因必填、并发更新后的草稿保留、读取失败重试、显式接受最新记录、已编辑字段保留与未编辑字段更新、读取/保存期间关闭保护、采购交接后的编辑锁定、另一会话已到货后的锁定、供应商单独修改不增加承诺历史，以及实际到货与完整历史查看。测试结束清理本次夹具。

标准类型检查、变更文件ESLint、构建和专项浏览器结果见 [验证记录](procurement-reply-verification.json)。较早整套BOM浏览器脚本已同步采购弹窗选择器，本轮未重跑该整套验收；此次采购专项不替代真实项目试运行或完整规格书签收。

在配置隔离测试库并构建应用后，可在app目录运行：

```sh
TSX_TSCONFIG_PATH=packages/core/tsconfig.json node --env-file=.env --import tsx scripts/npi-procurement-reply-browser.test.ts
```
