# 采购到货资料与保存恢复

对应规格书19.7、22：采购确认实际到货日期，可补充到货照片或资料；手机上的日期回复与确认尽量简短。

## 修复与交互

原采购弹窗的保存回调调用通用刷新函数。该函数把读取错误转为外层提示，并正常返回，导致已经写入成功、随后列表读取失败时，弹窗仍关闭。现在保存后单独读取采购清单，并核对返回账号；读取失败会留在弹窗中显示“已保存”，锁定表单，提供“重试刷新列表”。该按钮仅重复读取，不再次提交承诺或到货记录。

提交请求失败或响应不明确时，保存按钮暂时锁定，已填日期和说明保留。读取最新记录后，若版本未变可继续；有变化须显式核对；已经完成的记录显示实际日期并保持只读。

到货弹窗新增“保存并补充资料”：日期保存并完成列表刷新后直接打开该物料的附件窗口，采购默认分类为到货照片／资料。若保存后刷新失败，重试成功仍继续打开资料；也可在已确认保存后选择“补充到货资料”。响应丢失但重新读取已确认到货时，同样可补资料，无需再次提交日期。

照片上传、下载和权限沿用现有Document/Vault服务。入口始终使用原采购物料编号；不会因为该物料从未完成列表消失而丢失资料入口。

## 验证范围

- 5项内存组件检查：连续刷新失败、仅重试读取、保留资料跳转选择、承诺回复恢复、未知提交后读取、已完成锁定、读取期间关闭保护、账号变化。
- 专项浏览器使用3个采购件与两个自建项目。完成A后模拟两次清单读取失败，恢复时到货POST和完成事件各仅一次；完成B后模拟响应丢失，读取确认完成后无需重发POST。承诺回复后的账号不一致也被阻止，恢复后仅有一条首次承诺历史。
- 由采购账号从到货成功直接进入物料资料，上传测试PNG，检查Document/Vault关联的项目、物料、分类和上传人，并下载核对原始字节；另一个项目的物料没有该照片。
- 桌面和手机布局检查、标准类型检查、构建，以及原采购回复专项回归。详细结果见[验证记录](procurement-receipt-verification.json)。

浏览器使用独立无头Chrome、显式 `_test` 数据库和临时Vault。每轮清理自己创建的采购件、项目、用户、会话、原生资料及临时文件；未读写正式业务数据。本轮不改变后端日期、权限或完成规则，也不代表全系统最终验收。
