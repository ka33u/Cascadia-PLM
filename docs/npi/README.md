# Cascadia 新品制造协同开发与运行说明

本项目是在 Cascadia 开源底座中新增的独立 NPI 业务模块，依据用户提供的《Cascadia NPI SRS V1.4 数据库 API BOM导入开发版》开发。复用 Cascadia 的 Program、用户、登录会话、Hono、TanStack Router、PostgreSQL 与 Drizzle；与原“亨达新品开发”系统的代码、数据库、账户和端口独立。

当前已实现的业务包括建项、BOM导入及换版复核、制造四节点、BOM外物料、采购回复、承诺历史、齐套预测、异常驾驶舱、原生问题和附件资料。不是规格书所有扩展项的最终验收版本。实际用户、在研项目和供应商资料需要管理员自行录入，运行库未自动灌入示例项目。

当前导航、规格书要求和验证范围见 [规格书对照](srs-traceability.md)；交付与待验事项以 [当前状态](current-status.md)为准。管理员左侧有首页、新品项目、BOM管理、制造准备、采购管理、报表看板、基础数据、系统设置八个入口。“制造准备”处理四节点任务，首页汇总项目风险；独立新品例会已取消。其他岗位按权限显示入口。

## 本机使用

- 页面：`http://localhost:3410/npi`
- 管理员账号：`admin@npi.local`
- 随机初始密码见项目内 `.npi-local/首次登录.txt`，文件权限为仅本人可读，不进入 Git。首次登录后在 Cascadia 用户管理中修改。
- PostgreSQL 为新建的独立实例，端口 `55441`；开发库 `cascadia_npi`；测试库 `cascadia_npi_test`。数据库密码在本项目 `.env` 中，不输出到日志。
- 前端开发端口 `3410`，API端口 `3411`，仅监听本机。未配置开机自启、外网域名或公网发布。

运行环境：本机验证使用 Node 25.6.1、PostgreSQL 16.13。上游推荐的 PostgreSQL 18 环境尚未实测；不要把本机结果当作跨平台或生产验收。

从本项目 `app` 目录执行：

```sh
npm ci
npm run db:migrate
npm run dev:npi
```

若独立 PostgreSQL 未启动，在 `app` 目录执行：

```sh
pg_ctl -D ../runtime/postgres -l ../runtime/postgres.log -o '-p 55441 -h 127.0.0.1 -k /tmp' start
```

停止开发服务用 Ctrl+C；停止本项目数据库用：

```sh
pg_ctl -D ../runtime/postgres stop -m fast
```

请勿复用旧系统的数据库连接。`.env` 与 `runtime` 均为本机私有资料，不属于源代码。

## 管理员首次配置

1. 从NPI侧栏进入 Cascadia 系统管理，在用户管理中创建技术、制造、采购等实际账户。
2. 返回“系统设置”，为每个账号分配 NPI 岗位。主管可全局查看并按下述规则调整计划；采购只访问本人采购跟踪项及必要项目背景；技术和制造访问自己负责的项目。
3. 技术人员新建项目，指定技术负责人、制造负责人、要求齐套日期和样机要求日期。系统自动建立四个制造节点。
4. 图纸完成后按五阶段推进。完成项目之前，四节点与影响齐套的物料须确认完成。
5. “制造准备”集中回复四节点；“ERP BOM”上传并预览；“样机齐套”添加BOM外采购件。

“基础数据”维护导入模板，“系统设置”维护业务岗位。模板按名称、工作表或编号搜索，并可筛选启用/停用状态，每页10个；人员按姓名或邮箱搜索，并可按岗位或未分配筛选，每页20人。搜索、筛选变更后回到第一页；切换模块会恢复默认筛选。通用保存弹窗在数据刷新完成后关闭，避免紧接着操作时仍使用旧版项目。这里仅列启用用户，新增、停用系统账号仍从原生用户管理办理。

NPI业务岗位不等于完整PLM权限。采购被分配物料时不会自动加入 Program，也不会因此取得完整BOM、历史或其他采购件的访问权。上游 Administrator 具有NPI管理员权限；业务岗位映射与全部人员变更仍应按企业内部管理规则办理。

## BOM导入与模板

默认模板是 `ERP 母件结构表（多阶）`：工作表 `母件结构表-多阶`，第5行为字段名、第6行开始为明细；母件编码、名称和规格分别在 A4、B4、C4。两份真实ERP样本使用同一格式，不按电机型号写死解析。

“基础数据”提供可填写的模板表单：工作表名称、表头/数据起始行、母件单元格和Excel列标题逐项维护，无需编辑JSON。高级配置保留JSON入口；启用/停用状态显式保存，并有版本冲突保护。操作步骤见[模板维护说明](template-editor.md)。层级格式支持加号和数字；空编码、名称缺失、层级跳跃、数量错误阻止导入；规格、部门或仓库缺失仅提示警告。该首版只接收 `.xlsx`，不接收旧 `.xls`、宏文件、加密文件或带公式的工作簿。单文件上限5MB，ZIP声明展开上限20MB，单工作表上限5000条明细和150列。

数量按十进制精确处理，最多12位整数、6位小数，超出六位的小数按四舍五入处理并提示；舍入后为零或超出上限时阻止导入。数值单元格的微小二进制浮点尾差不产生舍入警告，文本数量按原文处理。换版用量比较使用精确值，可识别大数值的小数差异。原始行及完整原件保留。文本物料编码不转为数字，保留前导零，像 `87830900057E-48` 这样的合法工程编码不误判为科学计数法。

预览在服务器保存，绑定当前用户、项目和项目版次，30分钟有效。确认只接受预览ID，不能通过前端提交解析行篡改结果。预览一次性消费；新导入版本、明细、当前BOM切换和预览消费在一个数据库事务中完成。已修改项目或已有新BOM时旧预览被拒绝。

每次导入保留原始Excel的字节与SHA-256、母件、所用模板快照、操作者和时间。原件目前与NPI导入记录一同保存在 PostgreSQL 中，以保证导入事务的原子性；尚未接入原生 Document/Vault 的统一管理。原件通过鉴权接口下载时重新校验哈希。

重复导入不自动迁移或删除已有跟踪项。ERP BOM页会显示“换版待复核”，技术负责人或管理员可核对新版位置、数量、规格后关联原跟踪，或填写原因停止旧跟踪。关联保留跟踪编号、责任人、要求日期、首次/当前承诺及全部改期历史；名称、规格、数量和单位更新为新版值，旧值写入复核动态。完成项保留原版本，不改写。

匹配先比较完整父子路径、物料编码和行号，再为剩余唯一编码给出移动建议；同编码多位置不按行序猜测，需人工选择。差异支持新增、移除、数量变化、位置移动及未变化；移动同时发生数量变化时也显示前后数量。目标已跟踪时禁止覆盖，只允许关联当前版本的相同编码。跨编码替代和历史合并尚未提供。

未复核的旧跟踪继续有效，系统显示复核风险，涉及齐套时预测标为不完整。同编码旧项未处理前，禁止在新版重复新增跟踪。停止旧跟踪须填写原因，该项退出风险/待回复统计、采购待办和齐套预测；原记录在“承诺与动态”的历史物料中保留。普通跟踪设置中取消重点或齐套影响也须说明原因。

## BOM跟踪建议

模板可选映射“跟踪属性”列，属性说明见[模板维护说明](template-editor.md)。新导入仅按明确属性生成建议：一级核心自制加工件、一级新规格外购件，以及任意层级的长周期采购件、客户指定件、关键件。原材料、普通倒冲件、普通标准件、常备库存件默认不建议；明确的关键、长周期、客户指定属性优先于这些默认排除。

未映射或没有属性时不猜测，采购类型、部门和仓库不能证明新规格或长周期。未识别属性、已映射但缺失或重复的属性列会给出警告，负责人应人工核对。现有两份ERP样表没有此业务属性映射，仍可在任意层级手动设为重点。BOM外物料保持已有跟踪和齐套影响规则。

预览、BOM列表和确认弹窗展示建议依据。“建议待确认”只显示尚未纳入跟踪或齐套的建议物料，也可找到深层物料。建议本身不创建采购待办、不改变齐套统计；负责人确认责任人、要求日期及影响齐套后才生效。旧BOM的历史建议保留并注明需人工复核，不重新改写历史原件或已建立的跟踪关系。

## 项目问题

“项目问题”用于需要协调的设计、制造或交付异常。技术/制造项目负责人可新建问题，填写标题、说明、一般/重要/重大严重度、责任人、计划关闭日期，并关联整个项目、制造节点、跟踪物料或当前BOM中的任一物料。

问题复用原生 Issue，NPI扩展表只保存计划关闭日期及关联对象。修改标题、说明、责任人、严重度或目标日期时须说明原因，并核对版本。原始修改前后快照和处理记录可追溯。技术/制造责任人限于当前项目负责人；采购可分配为问题责任人。

采购在轻量工作台查看“我负责的问题”，可以添加处理记录、按原生生命周期推进状态，不能读取完整项目或修改问题基本资料。主管保持只读，无关账号不能访问。默认流程为新建→处理中→已解决→已验证→已关闭，也支持等待反馈、重新打开和取消等原生边；若管理员调整原生生命周期，NPI显示该生命周期实际提供的操作，不绕过其规则。

重大问题处于“已解决”或“已验证”时仍计入未关闭风险，关闭/取消后解除提示。超过计划关闭日期的问题另有超期提示。问题风险不擅自改动预测齐套日期。状态与状态处理历史由原生生命周期服务维护，NPI资料修改与补充记录保存在事件时间线。

## 项目资料、技术附件和照片

项目详情的“项目资料”页上传项目级规格书；物料或制造节点的“附件”入口保存技术规格、供应商资料和到货照片；问题详情中可上传问题照片/说明。支持PDF、PNG、JPEG、WebP、Word（.docx）和Excel（.xlsx），单份不超过5MB。手机可从相册或系统文件选择器上传。Word/Excel须未加密且不含宏，上传后作为原始附件保存与下载；Excel资料上传不会修改项目BOM，BOM更新仍走“BOM管理”的预览/确认流程。HEIC、CAD、旧版.doc/.xls及其他Office格式仍不支持。详见[Word与Excel资料](office-files.md)。

资料列表加载失败会明确提示并提供“刷新资料”重试，不会一直显示加载中。上传或归档已成功、随后列表刷新失败时，页面分别显示保存成功与列表错误；点击刷新即可重新获取列表，无需重复提交。重新获取失败时保留上次列表并注明状态，暂时停用上传和归档，成功后按最新权限恢复；未提交的标题和已选文件保留。

文件使用原生Document和Vault，NPI扩展仅记录项目/跟踪/问题归属、分类与归档原因。每次上传生成独立资料记录，不覆盖旧版；上传人、时间、字节SHA-256和原生提交可追溯。首次上传自动建立项目所属的私有资料Design，不改变任何Program成员或岗位。资料空间采用原生Document生命周期和分支策略，发布后仍服从PLM保护规则。BOM原始Excel尚未迁移，仍使用BOM版本原件下载入口。

技术/制造负责人管理本人项目资料，主管只读；采购只能读本人采购项附件、上传该项到货资料，并读写本人问题附件。采购不能查看项目资料列表、上传技术规格或归档。访问按当前责任人重新验证，上传者在交接后也失去访问权。已完成项目、已停止跟踪项及已关闭/取消问题不能继续上传。BOM同编码换版关联保留跟踪编号，因此其文件仍随原跟踪保留。

归档须填写原因，原文件及历史仍可下载；不存在物理删除或覆盖入口。文件内容和扩展名必须匹配，路径由服务器生成；下载再次核对哈希，PDF与Word/Excel均强制下载，只有PNG/JPEG/WebP允许登录后的缩略预览。所有文件响应禁止缓存和内容嗅探。相同上传请求重试只创建一份记录。存储失败或事务回滚清理新文件；若提交结果不确定且数据库不可达，则保留待核查，避免删除可能已提交的文件。失败的首次上传可能留下空资料空间。

**完整备份已包含Vault字节。**新版 `npm run backup:npi` 将数据库快照与附件一起保存并校验，使用 `npm run restore:npi` 恢复到新库和新文件目录。具体命令、恢复审计和限制见[备份与恢复说明](recovery.md)。自动调度及异盘保管仍需配置。

## 状态与齐套口径

所有状态由后端统一计算：已完成优先，其次逾期、待回复、风险、正常。日期按北京时间自然日比较，承诺当天仍不逾期，到次日才逾期。接口接受YYYY-MM-DD或带时区的ISO时间，统一转为北京时间业务日。

系统预测使用影响齐套且未完成的物料、工艺和工装节点承诺最大值。制造整体齐套是比较用的管理承诺，不参与自身预测；装配在齐套之后，也不参与预测。关键项无承诺时仍返回已知最晚日期，同时标记“预测不完整”。全部相关项完成时显示已齐备提示，预测日期为空，不制造虚假的未来日期。

制造承诺晚于要求时提示风险；明细预测晚于制造承诺时提示冲突和瓶颈。驾驶舱项目状态按最严重异常排序；待回复与风险KPI按存在对应异常的项目计数，因此同一项目可同时计入待回复和风险，不能将两项相加作为项目总数。已完成项目退出当前风险统计。

## 承诺、并发与历史

多人同时新建相同项目编号时，只有一个项目创建成功，其余请求明确返回“项目编号已存在”（`DUPLICATE_PROJECT_CODE`）。提前检查与数据库最终拒绝的提示一致，其他版本冲突保持原有处理；见[编号冲突专项](project-code-conflict.md)。

首次承诺永久保留；改期原因必填。每次更新携带当前版次，冲突返回409并保留界面输入。制造四节点集中提交整批成功或回滚。项目锁序列化该项目写入，承诺、历史和动态同事务提交。

重复确认同一实际完成日期返回已完成状态，不重复产生完成动态；已完成日期不能直接覆盖，未来实际日期被拒绝。没有删除跟踪项或清空首次承诺接口。数据库拒绝直接删除有NPI档案的Program、被跟踪的BOM行和被历史引用的跟踪项。纠错与正式归档/保留政策需要后续受控流程。

## 备份、恢复与升级

## 制造完成与项目结项

制造负责人可直接点击制造任务的“确认完成”，或进入项目的“制造准备”页点击“集中确认完成”，只填写本次实际完成的节点日期后保存。未填写的节点继续跟踪；已确认的实际日期不通过此入口改写。并发操作导致版本过期时，可在弹窗读取最新记录并核对，保留未完成节点输入后继续；完成已保存但列表刷新失败时，只需“重试刷新”。详见[制造完成快捷入口](manufacturing-completion.md)。

技术或制造负责人按顺序推进设计、制造准备、样机制作、样机试验、完成。进入制造准备须填写图纸实际完成日期；最后结项须先确认制造四节点及所有影响齐套项完成。结项窗口会列出未完成项，结项成功后项目转为只读。

集中完成接口：`POST /api/v1/npi/projects/:id/manufacturing-completion`，请求为 `{ expectedVersion, actualDates: { process?, tooling?, kit?, assembly? } }`。至少提交一个真实日期，服务端同事务处理并保留各节点完成审计。详见[第六轮验收](acceptance.md)。

## 物料计划交接与实际日期更正

项目技术/制造负责人或管理员可在物料/制造节点行点击“调整计划”，填写新的要求日期、物料回复责任人及原因。采购件只能交接给采购岗位，临时/自制物料交接给技术或制造岗位；制造四节点的责任人保持为项目制造负责人。交接立即更新待办与物料资料权限，不改写已有承诺日期与承诺历史。

已经确认完成但日期录错的项，负责人可点击“更正日期”，填写真实日期与原因。此操作保留完成状态、首次确认记录和全部更正记录；不能清空日期、填写未来日期或调整已结项/停止跟踪的记录。采购无调整计划或更正入口。如任务已完成，在采购筛选中选择“已完成”即可查看更正后的日期。

“承诺与动态”中的最近动态显示物料、操作人、前后要求日期/责任人/实际日期和原因；原始审计记录保存在数据库。项目负责人整体交接见下一节；代理回复及结项后的受控重开尚未实现。

接口：`PATCH /api/v1/npi/tracking/:id/plan` 接收 `expectedVersion`、可选 `ownerId` / `requiredDate` 和必填 `reason`；`POST /api/v1/npi/tracking/:id/completion-correction` 接收 `expectedVersion`、`actualCompleteDate` 与 `reason`。制造集中回复若通过API调整某节点要求日期，必须在 `changeReasons.<节点>Required` 中提供原因。

## 项目计划与负责人整体交接

当前技术负责人、主管或管理员可在项目顶部点击“项目计划与交接”。填写新品名称、型号、要求齐套/样机日期、技术/制造负责人和变更原因，先预览变更清单，再确认保存。

项目要求日期变动时，只有未完成且仍沿用旧项目日期的制造节点同步更新；自定义日期和已完成节点的日期保留。样机要求日期发生变化时同步原生Program目标结束日期；单独修改名称不会覆盖原生项目另行设置的日期。

交接会将制造四节点交给新制造负责人，并转交原技术/制造负责人名下仍在跟踪、未完成的非采购物料和未关闭问题。采购责任保持独立；已关闭/取消问题保留原责任人。当前技术负责人交出职责后返回新品列表。首次/当前承诺、完成日期和历史记录保留，审计同时保存负责人ID及当时姓名。

预览后的任务改期、完成、问题编辑或新增任务会使确认失效，需重新预览。项目、制造节点和原生Issue同事务变更，一处失败全部回滚；已结项项目仍为只读。

**主管权限：**主管可调整项目日期与负责人、未完成跟踪物料及制造节点的要求日期，并可交接物料回复责任人。修改必须填写原因；项目变更先预览再确认。承诺回复、完成确认和完成日期更正由原有责任岗位办理，不授予主管代填权限。主管交接后继续保留全局查看及计划调整能力。详见[主管计划权限与验证](supervisor-planning.md)。

**权限范围：**这里调整NPI职责及其项目管理访问，原生PLM“项目成员”资格仍单独管理，本入口不增删这些成员。管理员的全局访问、采购或历史独立任务的既有权限按各自规则处理，不把NPI负责人交接视为全系统权限清理。

接口：`POST /api/v1/npi/projects/:id/change-preview` 与 `PATCH /api/v1/npi/projects/:id/plan`。预览请求包含当前 `expectedVersion`、变更字段及 `reason`；确认提交相同字段和预览返回的 `expectedSnapshot`。变更字段包括 `name`、`motorModel`、`requiredKitDate`、`prototypeRequiredDate`、`technicalOwnerId`、`manufacturingOwnerId`。

## 今日变化与承诺改期筛选

首页驾驶舱在项目列表下方保留“今日变化”。“报表看板”展示今日变化与承诺改期任务，可先按项目、阶段缩小分析范围，再按物料或项目名称搜索两个明细区域。统计仅包含当前账号可见的项目；采购账号通过“采购管理”查看本人采购任务。

今日采用北京时间自然日：

- 新增逾期：当前仍在跟踪、未完成且逾期，相比前一日结束时新出现的任务。当天首次回复、改期或重新启用导致的新增逾期也包括在内；昨日已经逾期或今天已经解决的任务不计入。
- 承诺变更：今天实际修改承诺日期的记录，不含首次回复和日期未变的操作。同一任务当天多次修改分别展示，并保留操作人、前后日期和原因。
- 确认完成：物料或制造节点今天在系统确认完成的记录，按确认时间统计。今天补录昨天的实际完成日期仍计入；日期更正不重复计数。本区域不统计问题关闭或项目阶段完成。

改期任务默认显示累计至少2次改期的未完成跟踪项，可切换至少1、2、3、5次，并勾选“包含已完成 / 停止跟踪”查看历史。首次承诺、当前承诺和累计次数并列显示，交接与BOM换版关联不重置原任务历史。点击“查看项目”进入项目。主管可调整计划，承诺和完成由责任人办理，见[主管计划权限](supervisor-planning.md)。

接口 `GET /api/v1/npi/dashboard` 新增 `todayActivity`，返回 `day`、`newOverdue`、`promiseChanges`、`completions`。统计与项目状态在同一只读一致性事务中计算，读取相关当天审计，不受项目“最近100条动态”展示上限影响。这不是历史日报快照，跨期报表及大规模性能仍待完善。

## 客户与电机参数

新建新品可选填客户、用途/应用场景、额定功率（kW）、额定电压（V）、极数及项目说明。项目概览展示这些真实数据、创建人和创建日期；没有填写的字段显示“未填写”。已有项目通过“项目计划与交接”中的“客户与电机参数（可选）”修改，填写原因后预览前后值，再确认保存。

功率、电压为正数（最多12位整数及6位小数），极数为正整数（最多6位）；输入无需附加单位。这是数据格式校验，不代表电机选型校验。留空可清除已有值；API未提交某字段则保持原值。客户与说明复用原生Program字段，其余存入attributes.npiMotorSpec，保留其他扩展字段。创建与变更记录进入项目动态，沿用项目权限、版本及预览快照检查，无需新增数据库迁移。

## BOM保存草稿与继续导入

ERP BOM解析通过后可点击“保存为草稿”。草稿保存原始Excel及其校验摘要，不生成正式BOM、不改变当前生效版本与跟踪承诺。“我的BOM草稿”在刷新页面或重新登录后仍可读取，仅提供本人在当前有管理权限项目中的草稿。

点击“恢复预览”时按当前启用模板重新解析原始文件；上方指定模板时使用所选模板，否则使用原模板的当前配置。模板停用或格式变更导致失败时，原草稿仍保留，可选择正确模板重试。恢复后的新预览有效30分钟，需重新核对并确认导入；草稿本身不会随30分钟预览过期消失。确认导入只生成一个新版本，原件保存在正式版本中；同一草稿的其他已恢复预览随后失效。

“移除草稿”需要在卡片中再次确认，只从待处理列表归档并使关联预览失效，不删除已有BOM版本。保存、恢复和移除进入项目动态。草稿未通过解析校验时不可保存；已完成项目禁止草稿写操作。换技术负责人不会自动转移私人草稿，继任者需要重新上传原件。

新增迁移 `0010_npi_bom_drafts.sql` 在现有预览表增加保存时间、归档时间及来源草稿引用，不改现有正式BOM表。沿用 `npm run db:migrate` 应用迁移；迁移前应使用已有完整备份命令。

## 大BOM浏览与齐套数量

BOM预览、校验信息和正式明细每页100行，支持页码跳转、首末页。搜索和筛选针对全部行，展开收起后自动从首页显示；翻页不改变解析或导入范围，并回到新页开头；预览与异常件选择列表的内部滚动同时复位。桌面页首会避开固定项目栏。普通进入项目或返回工作台回到页面顶部，物料下钻仍定位到具体事项。当前单次上限仍为5,000行、150列、5MB压缩文件。

按已确认口径，齐套卡片“已满足”统计跟踪物料已完成项，“缺料”统计尚未完成项，包含启用的BOM外物料，不含制造节点或已停止且不影响齐套的项。这些是物料项数，不是库存数量或缺口数量。“未跟踪”单列当前BOM未进入跟踪／齐套范围的项，不推定其已完成。点击三个卡片可进入对应明细；点击“未跟踪”会打开当前生效BOM的未跟踪筛选，历史版本的跟踪记录不会减少该数。

## 制造快捷回复

“制造准备”任务列表的“集中回复”直接打开四节点日期表单；项目内同名按钮使用相同表单。首次可只回复已确认节点，改期必须填写原因。保存时防止误关闭；冲突后可在弹窗内读取最新计划，再显式载入并核对。状态数量已移到筛选栏前，按节点／项目／本人范围统计。详见[手机与快捷回复说明](manufacturing-quick-reply.md)。

## BOM读取与切换项目

BOM版本快速切换只显示最后一次选择的结果，读取中隐藏旧明细；最新读取失败时恢复已加载版本并显示错误。项目切换后，旧预览、草稿恢复、差异和刷新结果不会覆盖新页面。已提交的导入仍保存在原项目，成功提示注明项目名称。详见[BOM请求归属说明](bom-request-context.md)。

## 采购日期回复与到货

采购清单使用专用日期弹窗：首次只填预计到货日期，供应商与备注可展开补充；改变已有日期时才要求原因。冲突后可以在弹窗内读取并核对最新记录，保留手动编辑过的字段，更新其余过期字段，再保存。到货后从原附件入口补充照片与到货资料。详见[采购回复说明](procurement-reply.md)。

## 采购与报表分页

本人采购清单、今日变化和累计改期任务每页25条，顶部／底部均可翻页。搜索、筛选和统计覆盖全部可见记录，报表两张明细独立翻页；保存或刷新后按最新状态重新排序并回到第一页。详见[分页说明](list-pagination.md)。

## 驾驶舱聚合加载

驾驶舱和各模块列表已改为批量读取可见项目摘要；齐套、风险、累计改期与今日变化保留原口径。完整历史、参数和制造计划进入项目时再读取。1,149个测试项目的新旧对照中，SELECT从8,048次降到11次，JSON约减少60%。详见[加载优化及聚合接口字段说明](dashboard-loading.md)。这仍是全量可见项目汇总，尚未实现服务端分页。

## 项目历史完整浏览

“承诺与动态”页的承诺历史可按事项、回复人、日期和原因搜索，区分首次／改期，每页25条。项目动态按类型、日期和关键词从服务器分页，可继续查看100条以前的记录，保留操作人与完成、更正详情。顶部按钮直达两个历史区域。详见[完整历史浏览与接口参数](project-history.md)。

## 首页完整浏览

首页项目与正常项目分别按25条分页；今日待办和风险预警可展开查看全部、搜索及筛选逾期，支持直接定位事项和项目。计数仍覆盖全部可见数据。详见[首页分页与完整待办／预警](dashboard-browsing.md)。

## 采购到货资料与保存恢复

到货时可选择“保存并补充资料”，直接进入该物料附件。已保存但清单读取失败时可重试刷新，无需再次提交；提交结果不明确时先读取最新记录核对。详见[采购到货资料与保存恢复](procurement-receipt.md)。
