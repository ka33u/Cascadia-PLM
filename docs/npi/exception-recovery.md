# 制造异常件保存与BOM核对

对应规格书19.6：制造负责人从当前BOM选择异常件，保存预计完成、异常原因和齐套影响。后台继续使用原来的事务与项目／物料版本检查，不改动数据库模型或权限规则。

## 当前交互

保存确认成功后，若项目或驾驶舱读取失败，窗口保留“已保存”状态，锁定输入，并提供“重试刷新列表”。该按钮只读取最新项目、驾驶舱及账号信息，不再提交异常件。列表中确认存在已保存物料后才关闭窗口。

保存响应未收到或发生版本冲突时，保留输入并暂停再次提交。重新载入BOM后先展示最新版本、制造负责人、物料要求日期、首次／当前承诺、实际完成和齐套影响；用户明确核对后才载入新的并发版本。

同一BOM物料仍存在时，已编辑的日期、原因和齐套选择保留，未编辑字段采用最新值。BOM已换版导致原物料编号不在生效版本时，取消原选择，不按相同物料编码自动替换。选择新物料时采用新物料当前日期，并重新填写原因。已完成物料、完成项目、他人负责物料和已失去制造负责人权限的账号不能继续保存。

请求期间禁止重复提交和关闭。项目／账号改变或组件卸载后，较早请求不会触发关闭、刷新或覆盖当前窗口。错误和核对提示位于窗口顶部，手机可直接看到恢复入口。

## 验证范围

- 内存组件检查覆盖：已保存后的多次读取重试、未知响应后显式核对、编辑字段保留与未编辑字段更新、同编码换版重新选择、读取失败、物料完成、项目完成、账号／责任人改变、关闭与重复提交保护、卸载后的迟到响应、空BOM恢复和25项列表搜索分页。
- 专项浏览器使用两个隔离项目，每个25行合成BOM：首次保存后两次刷新失败只创建一个跟踪；并发改期冲突后保留草稿，最终仍保留首次承诺和同一跟踪编号；未知响应后只读取并检查记录；BOM换版后同编码新行不自动选中。
- 未知响应不被自动认定为保存成功，也不自动重新提交。浏览器核对后选择关闭，确认没有额外异常事件。若确需再次报告，应核对最新记录后明确提交。

可执行脚本为 `scripts/npi-exception-recovery-dom.test.mjs` 和 `scripts/npi-exception-recovery-browser.test.ts`。具体执行结果、日志、截图、实际运行模块与清理记录见[验证证据](exception-recovery-verification.json)。浏览器脚本要求显式 `_test` 数据库，结束后删除本次项目、人员、会话和模板，不接触正式业务数据。

本次为制造异常件专项验证，不代表完整SRS、真实项目试运行或历史完整浏览器验收已完成。
