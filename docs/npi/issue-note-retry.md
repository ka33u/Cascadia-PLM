# 处理记录重试

手机提交处理记录后，如果服务器已保存但响应丢失，可在当前表单直接重试。页面沿用这条记录的提交编号，服务端返回原结果，不再次追加时间线。

- 同一用户、同一项目、同一提交编号，只能用于同一问题及相同的处理内容。
- 同一编号同时提交多次，只追加一次。改用该编号提交不同内容或另一个问题，返回 409。
- 每次重试仍校验当前权限。问题交接后，原负责人不能凭旧编号访问或继续提交。
- 保存确认后，下一次填写生成新编号，即使内容相同也可作为新的进展记录。
- 表单内容改动后再次提交会生成新编号；刷新整页或关闭页面后，未确认编号不会继续保留。此时先查看时间线，避免把已保存内容另行提交。

接口 `POST /issues/:id/notes` 新增可选 `requestId`（UUID）字段。带编号的调用按上述规则去重，编号大小写等价。缺省时兼容原追加行为，不承诺去重。响应继续返回 `{ id }`，状态码为 201；相同请求的重试不改变原记录或时间。

重试编号随事件存储，去重查询和追加在同一个项目事务锁内完成。沿用现有事件表，无新增数据库迁移；不改变新建问题、资料修改或状态推进接口。

验证：36 项接口回归、6 项问题页面 DOM 测试通过，包含并发四次提交、冲突编号、独立用户、非法编号、旧客户端、交接撤权，以及响应丢失后沿用编号重试。真实浏览器布局未在本轮复验。
