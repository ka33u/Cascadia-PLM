# 首页项目、待办与预警完整浏览

规格书 BR-10、19.1 和 28.1 要求首页展示异常项目、今日待办和风险预警，并能进入项目或具体事项。

原首页待办和预警各显示前5条；“查看待回复”只筛选有待回复项的项目，“查看风险”依赖风险指标条件，无法保证包含仅逾期的所有任务或项目。记录较多时，项目表本身也会把后面的待办区域推得很远。

## 本轮改进

- 项目进度列表与折叠的正常项目分别按25条分页，提供顶部和底部翻页。异常排序和正常项目默认收起保留。
- 今日待办、风险预警默认仍展示前5条，明确显示总数；“查看全部待办／预警”展开完整记录，分别提供搜索、状态筛选和25条分页。
- 待办覆盖未完成、仍跟踪或影响齐套的待回复及逾期事项，排除已完成项目。可按项目名称、编号、型号、事项和责任人搜索；点击直接定位物料或制造节点，并同时显示要求与承诺日期。
- 预警覆盖逾期和风险项目，逾期优先。可按项目、型号和预警内容搜索，也可只看逾期或风险；点击进入对应项目。
- 项目、正常项目、待办和预警各自翻页；一个列表的搜索与翻页不重置其他列表。刷新数据或改变本列表筛选后回到第一页，避免停留在不存在的末页。
- KPI与计数仍依据当前账号全部可见数据；搜索覆盖全部记录，收起摘要会清空该摘要的筛选。

本轮为前端浏览分页，不修改后端风险规则或权限，也不减少驾驶舱接口的数据量。不是全系统服务端分页或压力测试验收。

## 验证

3项内存DOM交互检查使用132个项目，验证项目和正常组独立分页、KPI范围、页外搜索、待办及预警全量查看、纯逾期情况、实际定位回调、刷新和已停止跟踪／已完成排除。

独立浏览器专项使用自建的80个项目，包含26个正常项目、27个逾期项目、26个风险项目和1个待回复项目。遍历所有待办及53个预警，与后端项目摘要逐项比较编号；验证跨页搜索、独立分页、桌面与手机以及事项和项目的实际跳转。测试通过技术账号查看，浏览操作无业务写请求。

专项仅使用显式 `_test` 数据库，创建的项目、用户、会话在结束后清理；不访问正式业务记录。首轮脚本因把搜索输入当作普通textbox而定位超时，改为可访问名称定位后复验；未修改业务行为来绕过断言。当前结果见 [验证记录](dashboard-browsing-verification.json)。

实际构建也已通过专项，包括手机第二页翻页和无横向溢出；3410已提供新页面。查看[桌面](screenshots/dashboard-browsing-desktop.png)、[手机筛选](screenshots/dashboard-browsing-mobile.png)、[手机分页](screenshots/dashboard-browsing-mobile-paging.png)。
