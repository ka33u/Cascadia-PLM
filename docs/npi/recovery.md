# NPI完整备份与恢复

适用：本独立系统、PostgreSQL16、本地Vault。整套备份包含数据库、数据库快照引用的全部Vault文件（包括历史/软删除版本）及校验清单。BOM原始Excel、承诺历史、问题、项目、账号和岗位等随数据库保存。匹配版本的应用源码/构建、环境配置和数据库服务账号须另行受控保管。

## 创建备份

在 `app` 目录运行：

```sh
npm run backup:npi
```

输出为 `../runtime/backups/npi-<UTC时间>-<唯一编号>/`，包含 `database.dump`、`vault/`、`manifest.json`。目录权限700，文件600。清单记录PostgreSQL版本和快照事务开始时间`snapshotStartedAt`，完成时间与恢复点分开。已有旧`.dump`保留不覆盖；旧数据库单文件备份不能用新版完整恢复命令，仍需配套当时的文件副本。

工具从同一PostgreSQL重复读快照导出数据库、提取Vault引用、计算所有业务表的逐行摘要。应用端每次只读取一行，避免多份大型BOM原件同时进入内存。备份期间的新上传和改期不会混入该快照。每份附件复制时必须匹配快照中的大小/SHA-256。缺文件、损坏、冲突元数据、符号链接或复制失败会终止，不发布完成目录。完成目录只在所有校验通过后原子改名生成。进程突然退出可能留下 `.pending-*`，不能将其当作可用备份。

Vault根目录遵循应用规则：数据库`vault_root`设置优先，再使用`.env`中的`VAULT_ROOT`。备份目录不能放在Vault内部。暂不支持S3；发现S3文件会拒绝而不是漏备。源库必须是独立的`cascadia_npi`，命令不接受旧新品系统的数据库。

## 校验现有备份

```sh
npm run verify:npi:backup -- ../runtime/backups/<完整备份目录>
```

这会验证清单、数据库文件与每份附件的大小/哈希。它能发现损坏和不完整，但不替代实际恢复演练，也不是备份来源的数字签名。仅恢复你受控生成和保管的备份。

## 恢复到隔离的新库

```sh
npm run restore:npi -- ../runtime/backups/<完整备份目录> \
  --database cascadia_npi_restore_20260914_01 \
  --directory ../runtime/recovery-20260914-01 \
  --operator-email admin@npi.local
```

数据库名须为`cascadia_npi_restore_`加8～32位小写字母、数字或下划线；数据库和目录都必须尚不存在。不会使用`--clean`或覆盖已有数据库，不会更改运行系统的连接。CLI使用`.env`中的数据库连接权限创建新库；`operator-email`必须对应备份中已有的启用应用账号，用于记录新库文件目录调整的审计归属，不提供或扩大应用权限。

恢复过程：

1. 检查完整备份并拒绝已存在的目标。
2. 新建空数据库，以单事务恢复结构和数据。
3. 对每张业务表重新计算逐行摘要，与备份快照比对；再比较Vault元数据。
4. 复制并校验全部附件到新目录下的`vault/`。
5. 将**新库**的`vault_root`设置为新副本路径，记录指定的审计账号；生成`RESTORE_VERIFIED.json`。

校验失败时保留本次新库和`RESTORE_FAILED.txt`，不产生通过标记。不要使用失败副本接管业务；运行库不会被修改。表摘要先验证原样恢复内容，再单独调整Vault设置，报告明确记录这项恢复环境变化。后续业务读取可能写入正常访问审计，因此不要用运行后的数据库直接声称仍与快照逐字相同。

## 正式接管与日常运维

这两个工具不自动切换运行连接、不启动恢复库上的应用、不删除原库。实际接管前应核对恢复报告，并在独立端口验证项目、BOM原件、承诺/问题和附件；确认实际资料、人员及截止时间，再停写、切换环境连接并保留回退副本。

本轮完成的是手工完整备份及隔离恢复能力。还需要确定自动备份频率、保留周期、异盘或异地副本、加密保管和恢复时长要求。同一硬盘上的备份无法防御整盘损坏。大规模数据、S3、跨系统/跨PostgreSQL主版本恢复尚未验收。

## 自动化验证

```sh
npm run test:npi:backup
```

测试只创建随机命名的 `cascadia_npi_backup_*_test` 和 `cascadia_npi_restore_*` 数据库，并在`/tmp/npi-recovery-test-*`保存合成文件。覆盖并发期间一致快照、全部表恢复、原生业务读与附件下载、损坏拒绝、路径/符号链接边界、禁止覆盖、失败标记和无Vault设置时的恢复审计。清理只针对本次成功创建且有报告标记的测试库；运行库仅提供本机数据库连接配置。
