# 驾驶舱聚合加载优化

首页、新品项目、BOM管理、制造准备、采购管理与报表看板共用项目聚合数据。此前聚合接口逐个调用完整项目详情：每个项目额外查询7次，并把完整历史、最近动态、制造计划和项目参数一起发回，列表并不使用这些详情字段。

本轮改为按当前岗位可见项目批量读取，非空列表固定11次SELECT；没有可见项目时4次。完整详情与聚合列表共用齐套、风险、问题和换版复核计算。累计改期次数仍统计全部历史，首次回复与同日期补充不计改期；今日变化只读取北京时间当天的承诺和相关动态。查询仍在只读、可重复读事务内完成。

## 返回内容

`GET /api/v1/npi/dashboard`、`GET /api/v1/npi/projects` 和 `GET /api/v1/npi/workbench/manufacturing` 返回列表摘要。项目和跟踪项、各项统计、今日变化保持原口径，BOM版本摘要包含 `id`、`versionNo`、`rowCount`、`sourceName`。聚合项目不再返回 `history`、`events`、`profile`、`createdBy`、`plan`，也不返回BOM版本的母件、最大层级与导入时间。

这些完整资料仍由 `GET /api/v1/npi/projects/:id` 按原权限读取；项目详情接口未缩减字段。所有本系统调用方已经类型检查和页面回归。此次没有数据库迁移。

## 对照验证

同一隔离测试库、同一批1,149个项目的新旧实现对照：

| 测量 | 原实现 | 优化后 |
|---|---:|---:|
| SELECT次数 | 8,048 | 11 |
| JSON字节数 | 15,523,644 | 6,202,441 |
| 服务函数单次耗时 | 2,839ms | 123ms |

返回数据减少约60%。这是本机单次服务函数观测，包含既有1,146个测试项目和3个专项夹具，不能作为网络端到端响应时间、并发压力或生产性能承诺。聚合仍一次返回可见项目与跟踪项，服务端分页尚未实现。

对照按项目和事项编号核验所有共享字段、风险、齐套、问题数、BOM复核、指标和今日变化；排序时间相同的记录按编号规范化后比较。专项同时覆盖技术、制造、采购、主管、管理员、无项目人员与其他技术人员，验证跨日累计改期、未回复关键件、齐套承诺冲突、完成项目、逾期项、六位小数及完整详情历史。专项自建项目与账号结束后清理，既有测试数据保留。

复用验证脚本（从项目目录执行，必须配置显式隔离的 `TEST_DATABASE_URL`）：

```sh
TSX_TSCONFIG_PATH=packages/core/tsconfig.json node --env-file=.env --import tsx scripts/npi-dashboard-load.test.ts
```

需要对照旧实现时，在独立候选目录设置 `NPI_BASELINE_APP_ROOT` 为旧版本应用目录；两套实现注入同一个隔离测试连接。当前交付版本再与自身对照没有性能比较意义。详细检查结果见 [验证记录](dashboard-loading-verification.json)。

标准类型检查、构建、36项接口回归、候选八模块导航以及实际构建的采购／报表分页桌面手机验证通过。接口旧脚本曾因共享测试库存在多个同格式模板而失败，现固定样本显式选择标准模板，未调整业务匹配规则。接口套件按原设计保留合成记录用于诊断。实际浏览器的一次完成刷新观测为6,505,957字节／318ms；因接口回归新增了测试夹具，该值与上表不是完全相同的数据集。

本地3411进程工作目录为独立系统，启动时间晚于本轮源文件同步；3410页面返回200，匿名直连和代理API均返回401。未手动重启或写入正式数据。
