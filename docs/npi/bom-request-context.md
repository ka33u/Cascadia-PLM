# BOM版本切换与项目归属

依据规格书19.3、28.2的项目BOM版本和导入流程要求，修复慢请求在切换版本或项目后覆盖当前页面的问题。模板自动识别、原件保存和不可覆盖版本沿用现有实现。

连续选择V1、V2时，页面只显示最后一次选择成功读取的版本；即使V1更晚返回，也不会回到V1。读取中显示“正在读取所选BOM版本”，暂时隐藏旧版本明细、差异和原件入口。最新请求失败时保留之前成功读取的版本及明细，并显示错误；已经被新选择取代的请求失败不会再打扰当前页面。

解析预览、母件确认、草稿恢复、版本差异及项目刷新均校验请求所属项目和进入次数。切换到其他项目或离开后重新进入，同一项目较早的请求也不再覆盖当前状态。

已提交的保存草稿、移除草稿和正式导入仍在原项目完成，提示带原项目名称。导入期间版本选择暂时不可操作；若提交后切换项目，成功返回不会把原项目的新版本或预览写到当前项目页面。原API、权限校验、原始Excel与承诺历史保留机制继续生效，无需数据库迁移。

## 验证范围

在修复前的实际构建中，使用延迟响应复现了“先选V1再选V2，V1晚到后页面退回V1”。候选与交付后的实际构建均通过以下独立浏览器场景：

- 两个版本响应乱序，最后一次选择保持有效；旧请求失败被忽略。
- 最新读取失败后恢复已加载版本，读取中不显示旧版本物料。
- 版本差异、项目刷新、解析预览和草稿恢复的迟到结果不会污染另一个项目。
- 正式导入先提交、后切换项目、再收到确认：原项目新增一版，当前项目版本和物料保持不变。
- 桌面及手机无页面脚本错误，手机无横向溢出。

制造快捷回复专项回归同时通过，覆盖四节点保存、改期原因和历史、冲突恢复及跨项目导航。标准类型检查、变更文件ESLint和实际构建通过；3410前端模块已只读核查修复标记。

测试使用显式隔离的 `_test` 数据库、独立无头浏览器及两个临时项目，退出时清理本次夹具。此次验证不等于完整规格书验收或真实企业试运行。母件确认和草稿保存／移除的迟到结果检查来自源码审查，本次浏览器未单独延迟这些请求。

运行专项测试前先配置隔离测试库并构建应用，在app目录运行：

```sh
TSX_TSCONFIG_PATH=packages/core/tsconfig.json node --env-file=.env --import tsx scripts/npi-bom-context-browser.test.ts
```
