# 独立应用架构

前端为 React + Vite，使用独立应用入口、账号上下文和 NPI 页面。服务端为 Hono，数据访问采用 Drizzle + PostgreSQL，附件使用独立目录。没有原 PLM 的应用注册、通用 Item、生命周期引擎、Vault、CAD、消息队列、扩展模块或默认登录页。

```text
src/main.tsx → AccountProvider → 登录 / 我的账号 / 账号管理 / 新品工作空间
src/server/app.ts → /api/auth、/api/accounts、/api/v1/npi
src/lib/auth → 密码、会话、账号与岗位
src/lib/npi → 项目、BOM、承诺、齐套、问题、附件及审计
src/lib/db/schema → 18 张独立数据表
```

`projects` 保存项目身份和参数，`npi_projects` 保存排程和当前 BOM 基线。既有 API 的 `programId` 字段继续作为项目 UUID 使用，以保留业务数据及关联身份。它不依赖旧 Program 服务。问题完全保存在 `npi_issues` / `npi_issue_history`，附件完全保存在 `npi_attachments` 与独立文件目录。

## 账号与权限

管理员创建账号，分配技术、制造、采购、主管、管理员五种岗位之一。系统设置和独立账号页使用同一套账号服务。

| 岗位 | 权限 |
| --- | --- |
| 技术 | 创建项目；管理本人负责项目的参数、BOM、跟踪配置和问题 |
| 制造 | 查看本人负责项目；回复制造四节点、重点物料和实际完成 |
| 采购 | 只访问分配给自己的采购件、问题及其附件 |
| 主管 | 查看项目与报表；调整计划、负责人，填写原因；不代填承诺和实际完成 |
| 管理员 | 账号、模板及业务管理；仍保留操作审计与版本校验 |

接口重新核验当前启用状态、岗位和任务归属，不信任前端按钮是否显示。项目交接、问题交接、计划变更及审计在同一事务完成；外层项目锁防止等待期间继续使用旧负责人权限。

密码采用 Argon2id。会话使用 32 字节随机令牌，数据库仅存 SHA-256 摘要；有效期 8 小时，活动验证可续期。Cookie 为 HttpOnly / SameSite=Strict，在 HTTPS 下设置 Secure。连续 10 次密码错误锁定 15 分钟，并限制同一连接来源的登录频率。

首次创建、重置及旧版迁移的账号须先改密才能进入业务接口。停用、改岗、变更邮箱和重置密码使该账号原会话失效；本人改密使其他设备退出。管理员不能停用自己或移除自己的管理员岗位。账号修改需要原因和版本号。

## Issue #1：Windows 重复打包

移除了旧的自定义路径解析插件。新配置使用 Vite 内置 alias，并对 `fileURLToPath` 结果调用 `normalizePath`，统一 Windows 分隔符；React 与 React DOM 去重。

入口通过相对路径加载账号 Provider，消费页面通过 `@/` 加载同一上下文。测试验证二者解析 ID 一致、产物只有一个上下文 guard，并实际打开已登录和未登录页面。Windows 与 Linux 均在 CI 运行，防止只在 macOS 上验证而遗漏原问题。
